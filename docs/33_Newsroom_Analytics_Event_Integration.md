# Newsroom Analytics Event Integration

## Status

Implementation planned on 27 July 2026 before application code changes.

## Purpose

Extend the consent-aware GTM/GA4 foundation with durable newsroom interaction events that support editorial decisions, audience growth, sponsorship evidence and future media accreditation applications.

## Privacy boundary

- No analytics event is emitted before affirmative analytics consent.
- No article body, email address, authentication data, Sanity data or other personal information is included.
- Event values are limited to public page paths, public article metadata, search terms entered into the public search form and public link labels/destinations.
- GTM remains preferred when configured; direct GA4 remains the fallback.

## Event contract

### `page_view`

Emitted after consent for the current route and for subsequent client-side route changes.

Fields:

- `page_path`
- `page_location`
- `page_title`

### `select_content`

Emitted when a reader selects an article card.

Fields:

- `content_type = article`
- `item_id` using the public article route
- `item_name` using the public headline
- `content_group` using the public category label

### `search`

Emitted when the public website search form is submitted.

Fields:

- `search_term`

### `contact`

Emitted when the public Contact us email link is selected.

Fields:

- `method = email`
- `link_text`

### `social_click`

Emitted when a public social profile link is selected.

Fields:

- `platform`
- `link_url`

## Implementation design

- Add a small provider-neutral analytics helper that writes to `window.dataLayer` only after affirmative consent.
- When direct GA4 is active, the existing `gtag` function consumes the same data layer.
- Add a global client tracker for route views and delegated interaction tracking.
- Add explicit data attributes to article cards, the search form and footer links.
- Do not duplicate the initial page view generated by GA4 configuration; direct GA4 configuration will disable automatic page views and the tracker will own route-aware page views.

## Required production configuration

Configure one provider in Vercel Production and Preview:

```text
NEXT_PUBLIC_GTM_ID=GTM-XXXXXXX
```

or:

```text
NEXT_PUBLIC_GA_MEASUREMENT_ID=G-XXXXXXXXXX
```

Provider IDs must not be committed to GitHub.

## Verification required

1. Preview build succeeds.
2. No data-layer event is sent to a provider before affirmative consent.
3. Accepting analytics loads exactly one provider.
4. One `page_view` is recorded for the current route and each client-side navigation.
5. Article selection records `select_content` with the expected public metadata.
6. Public search records `search` with the submitted term.
7. Contact and social links record their respective events.
8. GA4 Realtime and DebugView display the events after production provider configuration.
9. Event names and parameters are documented in the monthly accreditation evidence procedure.

## Completion rule

This work is not complete until it is merged, deployed, provider IDs are configured, consent behaviour is verified and the events are visible in GA4 Realtime or DebugView.
